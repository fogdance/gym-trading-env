# FG Single3 Oracle 最优性验证

状态：IN_PROGRESS；本文件目前是算法与验收记录，不能作为O-Gate完成报告。只使用冻结TRAIN价格，不读取validation或封存Test。

## 精确目标与共享执行

正式目标使用原生Replay的float32反馈（同一步TP/early10先相加，再转换float32），有理数γ=332/333，第一条推进反馈指数0。γ=1单列诊断。决策t、反馈u，局部事件折扣γ^(u−t−1)，下一空仓决策延续γ^(u−t)。自然分钟只用于原V2 TP曲线。全TRAIN尾部未知的后续收益不在该有限观测目标内；未成交仓位保留删失，无虚构平仓。

原Env负责每个候选第一步ADD及真实拒单、原子开仓和完整平仓。后续时间索引用Env生成的可执行报价和共享`single3_exit_decision`定位事件；不复制Ledger、PositionManager、Driver或Replay。索引跳过的bar仍计入Env步数及有效bar年龄。量不足SL挂起、gap、MAIN/EXPIRY优先和入场barTP收盘确认遵循同一个Env。

## 资金状态省略前的证明

不能由“300000足以开一次3手”推断所有连续亏损路径资金无关。本实现先在含账户约束的问题上执行有证明的支配剪枝：

1. WAIT既无奖励也无现金流；alpha/lambda_capacity均为0；非TP和右删失交易的已观察反馈逐步非正。将其整个占仓区间换成WAIT，保持后续原时刻决策，折扣回报不下降。
2. TP局部折扣回报非正的完整区间也可删除。每个保留TP的实际净现金增量必须严格正（冻结费用下282 CNY）。
3. 检查TRAIN整份报价包络、保证金和最大费用，证明从初始300000出发的所有**保留TP路径**在任意入场/逆行bar资金约束均不触发，且无有限每日开仓次数限制。
4. 所以任意原始可行路径都可映射到价值不低的保留路径，保留路径资金不低于300000。此时省去资金状态得到的时间DP上界，必须由最终完整原Env账户真实执行达到。

该证明只作用于经精确剪枝的可达状态，不声称所有原始任意亏损路径资金无关。若成本变化、TP净现金非正、资金包络失败、有新奖励/等待现金流/交易限制，输出NOT_PROVEN，停止正式P4及下游。不会把资金风险不同的状态强行合并。

## 数值与独立验证

每个gamma幂、乘法和加法使用向外舍入区间；只有区间不重叠才直接选分支。重叠时以`Fraction`精确比较float32二进制有理数系数和γ=332/333，公共未来交易链精确相消。平分选择WAIT，不使用epsilon宣称最优。搜索状态预算每合约200万；资源不足不自动降级。

最小测试已实际通过5项：LONG/SHORT短OHLC全部请求动作枚举，以独立原Env账户得到精确有理回报；四候选×两个gamma与DP逐项一致；pending/gap/删失、元数据/量不足MAIN优先；资金证明失败拒绝；精确平分WAIT和状态预算拒绝。
