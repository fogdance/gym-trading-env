# 正式 TRAIN 18 合约粗估工期

按 20 个逻辑线程、每 worker 原生线程 1、逐合约依次生产：仅生成约 **2 天**；包含独立 Native G3、Reader 和覆盖验收约 **4 天**，排期预留 **5 天**。这是天级估算，不是 18 合约实测，也不是严格上界。没有为估算启动全量生产。

本轮 Gym `b10b764d2d1dc9ffb24c6450cef67ba0a378ec53`、Dreamer `b7a693b3c7b0b45eeecdec954818be42d40e67b6` 的真实 FG201 两日基准为 4,146 条记录：Generate 192.610s、独立 G3 175.288s、Reader 14.967s、完整流程 399.823s。按原生记录量简单外推约 38 小时生成、34 小时 G3、总计 78 小时；按天取整并留余量，得到上面的 2 / 4 / 5 天。

初始化开销不随行数线性增长；不同合约的真实持仓跨度、TP/SL 路径与完整主力期 L2 分数长度也不同。当前基准选择合约末两日，不能证明前中段长后缀的计算、输出体积或速度，也不构成可靠上界。完整主力期实际生产与时间：NOT_RUN。

当前正式 F1 入口要求真实 Native G3 与 Reader 身份/窗口验收，仅生成文件不足以开始正式 F1。F1 本身使用原生观测、动作、Reward、边界等训练世界模型，教师和 Actor 损失关闭；现行 Producer/Reader 认证仍绑定完整六行为 Corpus。上述时间不包含 F1 GPU 训练；正式训练授权没有发生。

用户后续要求行为规则可配置、可选择组合。仅 P4、P4+P1 等范围应在后续明确的新数据身份中实现；不能把改变采集分布当作本次逻辑等价优化。训练所需组合应由实际验证决定，六行为数量本身不证明训练效果更好。
