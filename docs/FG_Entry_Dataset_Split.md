# FG 数据切分：跨年份、月份与方向的完整合约分组

更新日期：2026-10-10。本文是当前切分说明。用户已停止旧日期切分训练，确认跨年份、交割月份和人工方向均衡分组，并补充 FG809=SHORT。本次已实现分组与训练抽样，未启动新训练。

## 1. 唯一配置入口

人工修改 `configs/fg_entry_v1/fg.yaml`，配置不分散到生成文件：

- `directions.intervals`：人工合约方向。`date_basis=trading_date`，夜盘跟随数据库交易日；内部时间区间为 `[start,end)`。FG809 标签覆盖 2018-04-11 至 2018-08-08，配置 end=2018-08-09，覆盖全部 28264 根记录。
- `data.split.mode=contract_groups`：不按全局时间边界切分。
- `data.split.contracts.train/validation/test`：冻结完整合约名单；`excluded` 当前为空。新增数据合约须人工分配；重复、遗漏和未知合约拒绝构建。
- `data.split.selection_seed=0`：本次制定名单的抽样种子，用于审计；构建只读取冻结名单，不自动重新选组。
- `data.split.training_order.mode=shuffle_each_epoch`、`seed=0`：完整训练合约的抽样规则。首次 reset 的显式 seed 优先，无显式 seed 时采用配置值；chunk reset 不重置抽样器。
- `data.excluded_contracts` 中的 FG805 是导出排除项；FG809 当前进入训练。

## 2. 数据来源与名单制定

直接使用已有 `artifacts/fg_entry_v1/main_export_345_audited/export_manifest.json`，没有再次导出数据库。只包含主力合约、日盘与夜盘，截止 2025-12-31；导出已截掉 23:01～23:30，保留 23:00，采用固定 345 分钟时钟。

制定名单时，候选输入按主力区段首时间戳升序排列，使用 NumPy default_rng(0) 生成 20000 个候选排列，各取 14/4/5 个完整合约；要求每组覆盖 01/05/09 月、LONG/SHORT、早期（首个时间戳年份≤2020）及近期（≥2024）。在合法候选中，按 LONG 数、三种交割月数量和早期/中期（2021～2023）/近期数量相对于组规模占比的平方偏差总和选最小值，平分时保留先遇到的候选。未使用收益、止盈次数或模型表现挑组。

这是小样本下的近似均衡，不承诺每个年份在每组都有合约。名单已显式冻结，构建不重跑候选搜索。

## 4. 训练打散与账户状态

每轮对全部 14 个训练合约无放回排列，遍历完才重新排列；两轮之间同一合约可能相邻，这是合法抽样结果。合约内部分钟严格递增，不打散分钟或 chunk，不跨合约延续价格窗口。

chunk 是训练切片，不是真实交易终止。chunk reset 继续当前账户、合约和分钟位置，不重新抽样，不免费清仓。只有环境报告真实终止后才切换下一合约；正常换主力按旧合约最后可成交价格退出，没有速度 Reward。保证金风控等原协议保持不变。

金融检查点 schema=2 保存 manifest hash、当前索引、合约排列、排列内游标、epoch、初始化状态、NumPy RNG 状态、已完成合约指标及当前真实账户。恢复后继续相同合约、仓位及未来排列。旧 schema=1 仅能用于旧顺序抽样模式，不能用于新的打散模式。

验证和测试按冻结名单的固定顺序逐合约运行，不使用训练抽样器。各对照策略须使用同一合约、价格顺序和账户规则。
