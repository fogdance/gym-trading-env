## 3. R0：冻结接口与逐步对账

1. 使用 `Driver(parallel=False)`、`FromGymnasium`、原 dtype/space wrappers 和原生 Replay。
2. 保留真实时序：`action_t` 是下一次待执行动作，`reward_t` 是已经发生的反馈。Sidecar 分别登记输入动作、输出动作、真实结果及时间。
3. 保留 Wrapper 的 `is_first/is_last/is_terminal`，另记金融账户身份、游标和边界原因。1024 截断续接的重复观察不计为新行情、成交或有效决策。
4. 每个独立策略/合约账户使用独立 Replay stream；存储 chunk 与 Env 截断分别审计。
5. 保存等待写盘完成，校验哈希、chunk 链和预期序列数，再使用原 Replay 加载 sample。字段及 dtype 保持现有契约，序列长度为 65。
6. 输出 `replay_contract.md`：时序、字段、边界、Sidecar 关联和加载方式。

## 4. R1：生成冻结语料

新增 CPU CLI：`generate`、`reconcile`、`audit`，支持冻结训练清单、策略参数、生成种子、输出目录及独立采样种子，不修改训练入口。

- 生成前校验 manifest、CSV、配置引用及实际交易日边界；不打开 Validation/Test 价格文件。
- 保留拒单、失败、浮亏、长期持仓、非 TP 退出、右删失和未平仓账户。
- 各策略独立原生 `.npz` Replay；另存逐步事件 Sidecar、成交/退出事件和终局账户快照。
- Sidecar 通过 `stepid` 对应 Replay 行，不增加模型观察字段。
- Manifest 登记行情、方向、代码、策略、种子、Env/Obs/Reward 版本及产物哈希。Canonical trace 内容哈希与物理 chunk UUID 分开。
- 逐轨迹生成并释放内存；文件校验和逐条对账通过后才登记可复用。拒绝覆盖已有结果；未完成尝试保留，重跑使用新尝试目录。
- 其他 Codex 可能并发修改文件；生成和复用均以登记的源码/输入哈希为依据。相关来源发生变化时拒绝混入同一数据身份。

## 5. R2：覆盖与真实 batch 审计

按策略、合约、年份、方向、日夜盘报告：合法 ADD 决策、请求/成交/拒单、主动/受限 WAIT、0/3/6 手状态、持仓年龄、TP、非 TP 退出、右删失和终局未平仓。

- 自然分钟持仓年龄桶：`<15`、`15～60`、`60～480`、`480～1440`、`≥1440`。
- 早期逆行复用现有诊断口径：首次反向 10 点，前 5 根 / 6～15 根有效 bar 分开；报告 OHLC 顺序歧义，不改 Env 的 V1 Reward。
- 分别报告唯一行情分钟、实际推进交互、Replay 行数、重复观察及多策略行情重用次数。
- 四组和全量 Uniform 池分别抽样，用 `stepid` 关联 Sidecar。上下文位置与其余 64 个位置分开统计，报告事件数量、batch 分布及零事件 batch 比例。
- 全量加载覆盖全部有效序列，禁止静默淘汰旧数据。报告实际磁盘空间、内存和序列数。
- 按现有 `train_ratio=64` 推算 100K/1M 的样本使用量及重复率；推算不触发训练。
- 输出 `replay_coverage.md`。正确性通过与学习覆盖是否充分分开陈述；不足时仅提出扩种子或混合比例建议。
