# DEV / DATA / FORMAL 分级（用户最新规则）

此规则按用户 2026-10-18 的明确指示执行；优先于将正式训练冻结流程套用到开发的历史说明。

| 要求 | DEV 日常开发 | DATA 教材生产 | FORMAL 正式训练 |
|---|---|---|---|
| CPU 合成、有限真实 TRAIN 调试 | 直接进行 | 允许 | 允许 |
| 全部代码 SHA 冻结 | 不要求每次修改执行 | 最终发布时 | 必须 |
| 完整原生 G3 | 不要求每次修改执行 | 批次发布前 | 必须 |
| 失败后修正、重试 | 允许 | 允许，保留结果身份 | 重新验收 |
| 金融撮合、账户、时钟正确 | 必须 | 必须 | 必须 |
| MACD 因果、Teacher 与 Observation 隔离 | 必须 | 必须 | 必须 |
| 大规模 GPU、完整 Checkpoint、研究准入 | 不要求 | 不要求 | 必须独立验收和授权 |

DEV 可以用临时目录、合成数据、有限真实 TRAIN 和最小定向测试。开发时记录测试命令与失败事实，不要求每次迭代另产一套正式认证。DATA 批次发布和 FORMAL 原有来源、金融、授权与准入条件不因此放宽；TEST 仍按当前任务禁止读取。

WP04 对应关系：`f1-prepare` / `f1-read-check` 默认 development，仅作工程检查；`f1-probe` 固定内置合成源、CPU、非认证工程结果。真实数据 read-check 不更新参数。native-verification 显式执行 G3；只有 G3 加外部授权才能走正式 F1 生命周期。此次精确冷恢复测试用合成源验证未来 FORMAL 的完整恢复合同，不把这些完整测试设为每次 DEV 修改的前置要求。
