## 2. 关键数学契约：同价格、同参考、同信息可见性

### 2.1 底层共同市场价格

两种尺度必须使用**同一真实合约**的原始一分钟 OHLCVOI、相同的价格单位和复权/换月政策。禁止 1m 用真实合约，15m 用另一个连续主力序列直接混合；跨真实合约切换处必须明确断开、标记不能跨合约聚合。不要为凑足24根而混用不同合约价格/OI。

### 2.2 单个决策时刻的公共坐标

对 Agent 决策时刻 `t`，定义可用的 `P_anchor(t)>0`：**优先取原一分钟观察在该决策时刻所使用的、已知的 `ref_close_t`**（通常是此前交易日收盘参考价），必须核验其 point-in-time 来源；原代码可能含首日 `first_valid_close` fallback、`ffill/bfill`，遇到无前日参考或来源证明不足时不能默许未来填补，应显式回退到 `t` 时刻已经观测到的合法 `Close_t` 并标记 `anchor_source`。使用何种 fallback 是数据契约，不可用未来才出现的首有效 close 填补更早决策。

本次决策窗口中的24根15m OHLC **全部**以这同一个 `P_anchor(t)` 变换，且仅使用该时刻可获得的历史桶：

`price_x_j = log(price_j / P_anchor(t))`，其中 `price ∈ {O,H,L,C}`。

配套生成**仅用于核对的**1m共同价格坐标视图：

`audit_1m_ohlc_shared[k,4] = log((O,H,L,C)_{1m,k} / P_anchor(t))`

和15m价坐标前四列逐个比较，聚合一致。`audit_1m_ohlc_shared` 不是训练 Observation，不新增到原18维，也不修改原1m Encoder。此测试辅助视图不计入 `market_context_15m[24,7]`。

**不可掩盖的兼容性事实**：原 `market_seq[60,18]` 并不是60×4 OHLC；部分原价格特征以**各历史行自己的交易日参考价**计算（例如 `obs_pct_chg_from_ref_t`、`obs_session_high_t`），另一些以 VWAP 或 session open 计算。跨交易日的60根 1m 历史时，原18维不能数学上被宣称为“每行均已用 P_anchor(t) 归一化”。

为满足**最终给 E 模型的两个尺度必须处于同一套价格坐标体系**，独立模块还应交付一个 **E 专用的、可选影子视图** `market_seq_e_shared[60,18]`：名称/顺序/维度仍对应18个既有特征，但**所有源码中依赖参考价格的价格水平及其衍生通道**均从当时已知原始1m价格、VWAP、日内高低值，**统一按当前决策时刻的 `P_anchor(t)` 重新计算，再按照各通道原设计做变换和裁剪**。优先审核 `obs_cumVWAP_t`、`obs_session_high_t`、`obs_session_low_t`、`obs_pct_chg_from_ref_t`、`obs_range_t`、`obs_dC_minus_cumVWAP_t`；核对完整公式后决定精确列表。与价格锚点无关的时间、成交量、OI、波动等维度不变，`obs_open_drift_t` 等**自身有明确经济含义的相对比值**不能被误认为绝对价格水平而强行替换。

影子视图**仅是独立数据模块的 E 候选输入，不得替换生产旧 `market_seq`**。新 E 模型集成时必须明确选择 `market_seq_e_shared[60,18]` 作为 E 版本实际一分钟输入，配合 `market_context_15m` 达成严格统一坐标；或者选择原18维兼容模式，但那时**不能宣称所有历史行同锚**。这是须单独 Review 的模型输入/迁移版本选择；影子视图能提前由本数据任务实现和验证。若选统一版本，旧模型权重仅能 **warm-start** 而非 exact-resume，需做编码数值差异和行为回归。

### 2.3 15m 数据窗口

- `market_context_15m`: `float32[24,7]`，最早到最新顺序。窗口由当前时刻**之前已经完整且可见**的15m桶组成，不包含正在进行的桶。
- 6个数据通道+1个mask：`rel_open,rel_high,rel_low,rel_close,vol_relative,oi_change,valid`。
- 不足24根左侧 padding 全零，mask=0；有效为1。没有人工市场结构、趋势类别、双顶、MACD、ATR或100分评分。
- 严格 finite，价格/成交量/OI 合法，预定时段数据不完整/重复/时间戳冲突时拒收该桶，事件日志说明原因。用户现有数据正常，异常分支属于防污染校验而非正常流程。
- 不断改变输入特征数量；不同参数/变换细节需要版本号+manifest hash，不能悄悄覆盖 schema。

**候选量仓最简规则**（需先用本地TRAIN数据检查数值分布再定 clip，不能声称已数据验证）：

- 15m `V_j = sum(合法一分钟Volume)`；`OI_j = 当桶最后一分钟OpenInterest`，绝不将 OI 求和。
- `vol_relative_j = log((V_j+1)/(mean(V_{j-20:j-1})+1))`，用该桶之前的合规完整桶作基准；不足所需历史时标记 warmup/invalid，不用以后出现的数据弥补。
- `oi_change_j = log(OI_j/OI_prev)`，要求同一真实合约、相邻合规已完成桶且 OI 为正。
- 先独立检查 FG 实际分布，包括 1%、50%、99%、最大值、clip 饱和率、warmup 占比、零成交、OI 跳变；提出有限裁剪区间并写入配置及 schema manifest，经确认后冻结。**不得将上一草案的默认裁剪范围包装成已验证最佳值**。

## 3. 时间、交易时段与严格因果

- 以原 Env **实际决策信息截止** `visible_cutoff(t)` 为权威：确认环境是在当前有效1m收盘后观察，还是下一步开盘前观察。不要仅凭文件时间戳猜测。
- 15m 桶的交易所日历、`trading_date`、夜盘、日盘休息时段、周末、假日，与现有官方期货时段一致；只由单一连续交易时段内的15个预期合法分钟组成，不跨中场休市/夜盘间隔拼凑。
- 时间桶必须存 `bucket_start`, `bucket_end`, `available_at`, `source_contract`, `trading_date`, `complete` 元数据；高周期可用性使用 `available_at <= visible_cutoff(t)`，并检查 End 不晚于当时可见。若真实数据 API 另有到达时间，按更晚的可用时间处理。
- 15m 在第14个可见分钟仍不可用；第15个分钟收盘及到达后才可加入。边界分钟必须用原 Env 最小受控例子判定，避免 off-by-one。
- 只用真实已完成的15m值，不把第1~14分钟的临时高低点伪装成最终高低点；近期行情仍由1m观察承担。
- **双向因果测试**：在 t 截断源行情 vs 用完整数据运行后读取 t 的结果，必须逐位/容差一致；在 t 后任意篡改全部未来的 OHLCVOI，t 的输出及元数据不变。
- 重复数据/无效分钟不能被 `resample('15min')` 不加校验地吞并；0成交但真实合法一分钟不等于丢失分钟。需要逐桶验证完整预定分钟槽和唯一性。
- 不把绝对自然分钟时差用于 Reward/Oracle；15m 分桶遵循交易时段和合法市场 K 线，市场分钟时钟仍由原系统负责。

## 4. 独立组件 API 与固定产物

建议最小纯数据接口（可按现有 Python 风格适度调整）：

```python
build_e_data_v1(
    minute_bars,            # 同一真实合约、含原始 OHLCVOI 与时段/有效性
    decisions,              # 原 Env 实际决策时刻、visible_cutoff、原minute obs引用
    schedule,
    config,
) -> EDataBundle
```

`EDataBundle` 包括：
- `context_15m`: `[N_decisions,24,7] float32`；新增15m模型输入。
- `market_seq_e_shared`: `[N_decisions,60,18] float32`，**仅供新 E 版本选择**的统一价格锚点1m影子视图；与不可变的旧18维同时保留。
- `price_anchor`: `[N]`，审计/复现元数据，不是新模型输入。
- `audit_1m_ohlc_shared`: 可按需只在测试模式生成 `[N,60,4]`；不进入 Agent。
- `bucket_manifest`, `decision_meta`, `schema.json`, `provenance.json`；标注每个历史上下文所用桶结束时间、来源身份、anchor来源、mask。

独立 CLI 建议（以 Codex 实际代码为准，不应声称已实现）：

```bash
python -m e_data_v1 inspect --source <READ_ONLY_TRAIN_SUBSET> --out <SEPARATE_DIAG_DIR>
python -m e_data_v1 build --source <READ_ONLY_TRAIN_SUBSET> --out <SEPARATE_OUTPUT_DIR>
python -m e_data_v1 verify --bundle <SEPARATE_OUTPUT_DIR>
```

数据规模先用适量 **只读 TRAIN 样本**和几个自造极端时间场景验证；必要时运行 CPU 全量 build 性能诊断，不启动GPU、不额外创建训练 Run。输出存独立实验目录，不写回行情数据库、不重写原特征缓存和旧 Checkpoint。

## 5. 必须实现的 CPU 测试和失败条件

| Test | 验证内容 | 通过条件 |
|---|---|---|
| F01 坐标一致 | 同一个 `P_anchor` 下真实1m价格与由其聚合的15m OHLC使用同一单位/坐标 | 原价重建/对数关系一致；两个近高点 log 差 = log(H2/H1)，非另取参考 |
| F02 原18维回归 | 独立模块开关前后 `market_seq[60,18]` 字节/容差、顺序、mask和原 provenance | 完全不修改，失败即BLOCK |
| F03 同一时点因果 | full data / prefix data / 改写全部未来 | 输出同一；后续修改不影响过去，失败即BLOCK |
| F04 桶边界 | 每个15m桶完成前/完成当刻/下一1m决策 | 仅在实际上线可见后新增，off-by-one失败即BLOCK |
| F05 交易时段 | 夜盘跨日、日盘午休、周末、假日、合约换月 | 不跨休市/不同真实合约组桶，不凭自然时间填虚假行情 |
| F06 聚合恒等式 | 15m O/H/L/C/V/OI 与其15个1m源数据 | O=首O,H=maxH,L=minL,C=末C,V=sumV,OI=末OI |
| F07 量仓时序 | 每桶量基准只来自以前的桶，OI非相加且同合约 | 数据重排/截断回归一致；跳变/异常有清晰报告 |
| F08 输入边界 | 24×7、旧到新、左填0、有效mask、float32 finite | 一致且可重复；padding不伪造交易 |
| F09 交易日换锚 | 60×18跨两个交易日、旧ref按行变化 | 原18维完全不变；E影子18维按当次决策统一锚点重算相应通道；1m审计OHLC与15m相同坐标，报告数值差异 |
| F10 输入来源 | 扫描产物是否含 Oracle未来标签、Teacher结果、当时不可见值 | 只含市场已知信息；教师数据不能进入上下文 |
| F11 运行隔离 | 原 Trainer/Archive/W&B 正式文件与库完全未改动 | `git status`/hash/路径检查通过 |

再增加 **真实FG TRAIN样本数值审查**：有效桶数、warmup数、价格/量/OI尺度、clip饱和率及吞吐速度；明显异常时报告阻塞，不以 `nan_to_num(0)` 隐藏问题。
