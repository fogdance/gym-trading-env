## 4. 顺序训练与恢复（替代原轮转默认设计）

1. A、B、C 各阶段均按真实合约起始时间顺序推进，不启用 `least_progress` 或跨合约账户 bank。
2. 原有 1024 根同合约 chunk 保留：chunk 后继续同一游标、持仓、资金、费用和 Reward 去重状态，不切合约。
3. 只有当前合约真实终局且已平仓后才进入下一合约；所有合约结束后从头开始下一轮。
4. 终局未成交保留亏损并拒绝 reset；保证金不足退出仍遵守独立风险协议，不为覆盖而改变业务。
5. Env 账户仍使用原有 schema1；外围新增 FG_FULL_V1 完整学习状态快照，精确保存 Replay/预取/Ratio/Gate/Driver，不增加账户调度器。
6. 顺序覆盖报告按每次实际访问前缀累计，提前 MARGIN_CALL 不能算作完整遍历。10 万先导不要求全历史覆盖；正式覆盖必须按实际推进结果验收。

数量审计见 `FG_DreamerV3_ABCD_Sequential_Coverage_Audit_V1.md`。四 fold 所有正式阶段正常遍历预算均足够。v1 轮转保留为旧实验能力，不作为默认，也不原地迁移其检查点。

## 5. C 阶段迁移

普通同运行恢复：使用 FG_FULL_V1 完整恢复模型、优化器、Replay 索引与在线队列、预取批次、训练/报告 carry、Ratio、Driver、账户、随机计数、Gate 及未评估统计。Gate/报告每 5000 环境步、常规保存每 10000 步，常规保留两点，分支与最终节点永久保留。

C 跨阶段：与 A 共享全历史前缀，正式读取精确 700K 节点、先导读取 70K。校验源 fold、seed、节点实际预算、模型/训练/代码/依赖身份；完整加载 Agent 及优化器，保留更新与随机计数、action-mask warm-up/gate 学习状态。新的近期训练流、账户、Replay、Ratio 和待评估统计重新建立。源节点预算可以小于源 A 的最终目标。

近期阶段使用新进程、新日志目录、空的 B-only Replay 和新 B 账户；预训练账户完整归档，包括未平仓亏损。此迁移是模型学习迁移，不是同一投资账户连续收益。

近期局部交互步从 0 计，另存 70000/700000 的累计偏移；训练 Ratio 和流从近期初始化，防止补跑历史更新。近期运行再次恢复时优先恢复自身完整 checkpoint，不重复执行阶段迁移。

## 6. 统一评估与择时诊断

相同完整验证行情、初始本金 300000、方向配置、成本和成交协议。策略：Always ADD、Random ADD（固定 p=0.5）、Rule ADD（现有 20 根/5 点回撤）、确定性 Dreamer。

主指标：`reward_per_day = total_reward / eligible_trading_days`。分母使用方向有效且可观察的交易日，所有策略固定一致；同时输出原始日数和 NO_TRADE 日数。主动 WAIT、满仓不能缩小分母。

必须输出真实 TP 批次、成功等待中位数/P90、含失败与删失的固定 horizon 成功统计、期末未完成批次/手数、强退结果、逐笔 MAE、组合最大浮亏、MTM 权益回撤、费用、已实现损益、期末净权益、6 手满仓可交易时间占比，以及主动/受限 WAIT、请求/成交 ADD。

Matched random 使用独立闭环账户，seeds 0～29。以 Dreamer 的实际开仓成交按交易日、方向、日/夜盘、下一开盘分钟索引的 60 分钟桶建立配额。候选信号处按“剩余配额 / 剩余已知时钟候选数”采样，只使用自身当前合法动作和成交约束；配额仅在真实开仓成交后减少。

不得读取未来合法 mask、价格、成交量或 TP 来选择随机入场。无法实现配额时输出逐桶差异与 `partial_match`，不扩桶或绕过仓位限制；不得据不完全匹配宣称等频择时优势。这是条件于 Dreamer 轨迹的事后诊断，不是可部署随机策略。

报告配对 Reward/day 差、成功率和等待分布，保留终局失败与右删失。随机 seed 分布不等于市场置信区间；少量合约的相关性必须说明。

评估文件：`trades.csv`、`episode_metrics.csv`、`policy_actions.csv`、`matched_random.csv`、`comparison.md`，并保留真实成交、奖励对账和完整账户快照。
