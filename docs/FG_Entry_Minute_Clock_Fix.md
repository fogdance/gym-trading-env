# FG 分钟索引因果性与导出截断

## 已复现的问题

FG 的真实期货路径按输入行数生成 `minute_index_t`，归一化分母又用当天输入数据的最大索引。对真实 FG301 行情，同一第 60 根数据，完整 345 根输入为 `59/344 = 0.17151162790697674`，前 60 根输入为 `59/59 = 1.0`。差异来自未来数据是否已经加载，不是价格变化。

旧的严格 345 时钟路径通过 `reindex` 静默丢掉 23:00 后行情，而 FG 真实时钟路径会保留这些行情。两条路径行为不一致。

## 用户确认的最终规则

统一使用 345 分钟名义交易时钟：21:01～23:00、09:01～10:15、10:31～11:30、13:31～15:00，均为一分钟收盘时刻。人工维护入口是 `configs/fg_entry_v1/fg.yaml` 的 `market_clock`。

保留早期交易日，在 FG 导出阶段截掉 23:01～23:30，保留 23:00。没有兼容历史 375 分钟时钟，也没有丢弃整个早期历史区间。原始导出快照保留，没有重新查询数据库。

`minute_index_t` 按已知时段和当前时刻计算，`obs_minute_index_t = minute_index_t / 344`。日盘首分钟始终是索引 120，即使当日没有夜盘或只加载日盘。日夜盘字段直接使用当前时刻，避免依赖整段数据最大索引。FG 输入若仍含 23:00 后行情会报错，要求先在导出阶段处理。

观察维度仍为行情 `(60,18)`、仓位 9 维；Reward、入场手数、止盈、成本和仓位协议不变。此次不修改旧 FX 特征行为。行情时钟版本进入账户配置指纹，禁止旧金融检查点无提示混用。
