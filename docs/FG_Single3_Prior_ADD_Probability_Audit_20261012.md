# FG Single3 prior ADD 只读概率审计（2026-10-12）

本次不启动训练、不修改 Gate 或冻结参数、不访问 DEV/TEST；对两个现有训练权重做 CPU 推理。

## 输入与口径

在线 180,000 环境步 Checkpoint 的 Replay 共 180,000 行。固定不重叠的 64 个评分位置及 1 帧因果上下文，共 179,968 个唯一评分位置，其中 1,016 个允许 ADD（0.565%）。尾部不足 64 帧的部分及首个上下文位置未评分。
两个模型使用同一批观察、真实历史动作、本次审计的推理随机种子202、原 B16×65 输入，以及原 `recompute_prefix` 和 availability head。模型原训练种子仍为0。首先应用原生 `Replay._annotate_batch`，包含样本首帧重置及 is_last 标注，再重建因果上下文。未调用优化器或 Agent 的策略缓存；使用 Checkpoint 的训练参数。prior 不读取本帧观测，post 吸收本帧观测（其中包含当前真实 Mask）。
样本来自原在线 TRAIN Replay，不做正类过采样。Checkpoint 的模型、配置及 Replay 数据哈希已核对；源 Checkpoint 模型文件在推理后再次核验。只读扫描的概率判定阈值不是 Gate 的质量门槛，两者不能混淆。

## 建议的后续步骤

保留现有 Gate 的召回、FPR及20次窗口门槛。先针对FG009释放状态核对预测与交易事件、当前市场特征和训练覆盖；并将0.20判定阈值作为另行验证的候选。采样或可用性损失的改动需要独立证据，不能据此改Reward、horizon、网络或回放混合比例。任何阈值调整均须记录协议并实际验证连续窗口及想象轨迹，不能通过改旧身份或旧Checkpoint启用。

本次的单合约曲线不证明所有模型的理论上限，也不能单独推导原有全局Gate必然无法开启。它说明单一全局阈值并未解决当前模型在近期合约上的识别不足。

## 结论范围

本次能确定固定模型的漏判集中位置、同样本训练前后差异以及概率判定阈值的取舍。没有证明新的采样、损失权重或网络必然有效，也没有证明市场事件不可预测。
聚合可达性不等于正式 Gate 通过。本次没有验证连续 20 个在线报告窗口、15 步自由想象轨迹的 Mask 回退率、未来 TRAIN 区间或独立 DEV 的稳定性。所有现有 Gate 门槛和实际概率判定阈值均保持不变。

CPU 与 CUDA 的浮点舍入及采样实现存在数值差异；两模型对照采用同一 CPU 后端、原 bfloat16 计算类型和同一组种子。结果是当前种子与固定分块条件下的测量，不是对所有随机种子的估计。
